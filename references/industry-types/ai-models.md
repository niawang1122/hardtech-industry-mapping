# 适配指南：AI 算法/模型类

**适用行业**：世界模型、具身智能大模型、多模态基础模型、AI Agent、视频生成模型、科学计算模型（AI for Science）

**这一类需要对主框架做最大幅度的改造。** 硬件行业的很多概念在这里不适用，硬套会得出错误结论。

## 核心差异：为什么不能照搬硬件框架

| 维度 | 硬件行业 | AI 模型行业 |
|---|---|---|
| 壁垒来源 | 产线、设备、专利、工艺 know-how | 人才密度、数据资产、算力储备、工程经验 |
| 代差稳定性 | 稳定，追赶需数年 | **极不稳定，可能几个月被追平或反超** |
| 复制难度 | 极高（需重建产线） | 相对低（论文公开、开源模型、人才流动） |
| 规模效应 | 产能规模 | 数据飞轮、算力规模 |
| 竞争者 | 主要是公司 | 公司 + 高校实验室 + 开源社区 |
| 主要风险 | 技术做不出来 | **做出来了但被大厂顺手覆盖** |

## 产业链重新定义

不要套用"材料-设备-制造-封装-应用"。改为：

| 层级 | 内容 | 关注点 |
|---|---|---|
| **上游-算力** | GPU/加速卡、云服务、算力租赁 | 算力可得性（对中国项目尤其关键）、成本结构 |
| **上游-数据** | 数据采集、标注、仿真环境、合成数据 | **数据是否构成壁垒？能否被复制？** |
| **中游-模型** | 架构设计、预训练、后训练、评测 | 架构路线、训练方法、评测基准 |
| **中游-工程** | 推理优化、部署框架、模型压缩 | 推理成本是商业化的关键 |
| **下游-应用** | 机器人、自动驾驶、游戏/内容、工业仿真等 | **价值捕获在哪一层？** |

**关键问题**：这个行业的价值最终会沉淀在哪一层？如果模型层最终商品化（commoditized），那么投模型公司就是错的。这个判断必须在报告里明确讨论。

## 技术路线 = 模型架构路线

以世界模型为例，技术路线可能包括：
- 视频生成式（直接预测未来帧）
- 隐空间预测式（在压缩的隐空间中预测，如 JEPA 系列思路）
- 神经辐射场/3D 表示式
- 物理引擎混合式（神经网络 + 显式物理仿真）
- 自回归 token 式

**原理部分要讲清**：
- 建模方式（世界的状态怎么表示？）
- 训练目标（优化什么损失函数？为什么这个目标能学到世界规律？）
- 推理方式（怎么用它做预测/规划？）
- 数据需求（需要什么样的数据？多少量？怎么获取？）

**双层解释同样适用**。例如：
- 小白版：视频生成式世界模型像"一个看过海量视频的人，你给他前几秒，他能画出接下来会发生什么"；隐空间式像"他不画出画面，而是在脑子里想'接下来大概是这么个情况'，然后直接基于这个抽象判断做决策——省掉了画画的力气"
- 专业版：讲清各自的损失函数、表征学习目标、以及为什么隐空间方法能避免把算力浪费在预测无关的像素细节上

## 关键指标要重新定义

不是速度/容量/功耗，而是：

| 指标类别 | 具体指标 | 说明 |
|---|---|---|
| 能力 | 长时序一致性、物理合理性、可控性、泛化性 | 这些往往**没有公认的量化标准** |
| 效率 | 训练算力（FLOPs）、推理成本（$/次）、数据效率 | 推理成本决定商业模式能否成立 |
| 工程 | 延迟、吞吐、部署门槛 | 具身智能对实时性要求极高 |

**必须明确说明：这个方向目前有没有公认的评测基准（benchmark）？**

如果没有（新方向通常没有），这本身是极其重要的信息：
- 意味着各家宣称的"SOTA"无法横向比较
- 意味着尽调时无法用第三方数据验证项目方的说法
- 意味着"谁领先"这个判断本身就是模糊的

这一点要写进"最容易理解错的地方"。

## 代差判断要重新定义

**不是制程节点，而是**：
- 模型能力水平（在可比任务上的表现）
- 数据规模与质量
- 算力投入规模
- 人才密度
- 开源/闭源生态位置

**必须强调的特性**：算法类的代差**极不稳定**。硬件的代差需要数年追赶，而算法的代差可能因为一篇论文、一次开源、一个团队流动而在几个月内被抹平甚至反超。

**投资含义**：不能把"当前领先"当作护城河。要追问的是：**这个领先是靠什么维持的？** 如果只靠算法巧思，护城河约等于零；如果靠数据飞轮或独特的数据资产，才可能持续。

## 竞争格局的特殊处理

竞争者不只是公司，要分三类：

| 类型 | 特点 | 尽调关注点 |
|---|---|---|
| **大厂内部团队** | 算力和数据资源碾压，但可能不聚焦 | 大厂是否会认真做这个方向？ |
| **独立创业公司** | 聚焦、灵活，但资源受限 | 融资能力、算力获取、人才留存 |
| **高校实验室/开源社区** | 可能免费释放能力，直接摧毁商业模式 | 该方向的开源进展速度 |

**报告中要明确讨论**：这个方向被大厂或开源"顺手做掉"的概率有多大？项目方对此的应对是什么？

## 市场规模部分的特殊处理

**这类方向几乎肯定没有可靠的市场统计。** 不要硬找数字。

正确做法：
1. 明确说明"该方向尚未形成独立的市场统计口径"
2. 转为分析**下游应用的市场空间** × **该技术在其中的价值捕获比例**
3. 把价值捕获比例的假设明确写出来，并说明它取决于什么条件
4. 说明这是推算而非统计

例如世界模型：不去找"世界模型市场规模"，而是分析机器人、自动驾驶、内容生成这些下游市场的规模，再讨论世界模型在其中能捕获多少价值、以什么形式捕获（授权？API？自建应用？）。

## 尽调清单的调整

**团队**：
- 顶会论文（NeurIPS、ICML、ICLR、CVPR、CoRL 等）第一作者
- **是否有大规模训练的实战经验**（跑通千卡集群和写论文是两回事）
- 工程能力与研究能力的配比（很多学术团队缺工程）
- 关键人流失风险（AI 人才流动极快）

**技术**：
- **数据从哪来？能否被复制？** 这是最关键的问题
- 算力从哪来？成本多少？中国项目还要问算力可得性
- 有没有第三方可验证的结果？如果没有公认 benchmark，怎么证明？
- **推理成本是多少？** 商业化的核心约束

**最容易被美化的位置**（写进易错点清单）：
- Demo 挑选：展示的都是精心挑选的成功案例，失败案例不展示
- 评测基准自定义：自己设计对自己有利的评测
- 与不公平基线对比：拿自己的最新模型和别人的旧版本比
- 用"能力涌现"掩盖不可控性
- 论文指标与产品体验脱节

## 风险提示必须新增的条目

| 风险 | 说明 |
|---|---|
| **被 Foundation Model 覆盖** | 大厂的通用模型能力提升后，专用方向可能失去存在意义 |
| **开源冲击** | 开源模型追平后，闭源商业模式崩塌 |
| **代差不稳定** | 领先可能在几个月内消失 |
| **人才流失** | 核心研究员被挖走可能直接导致项目失败 |
| **算力约束**（中国项目） | 算力获取受限，训练规模上不去 |
| **评测不可信** | 缺乏公认基准导致无法验证真实能力 |
| **推理成本不收敛** | 技术能力达标但单次推理成本过高，商业模式不成立 |

## 投资逻辑的调整

硬件行业的"卖铲人"逻辑在这里依然成立（投算力、数据、工具链），但"国产替代"逻辑要谨慎——算法层面的"替代"和硬件不同，因为算法本身不构成卡脖子（除非算力受限）。

更适用的逻辑：
- **数据壁垒逻辑**：投那些拥有难以复制的数据资产的团队
- **场景绑定逻辑**：投那些深度绑定特定高价值场景、能形成数据飞轮的团队
- **工具链逻辑**：无论哪条模型路线赢，训练/推理/评测工具都有需求
- **谨慎对待纯算法创新**：单纯的架构巧思很难构成持久壁垒
